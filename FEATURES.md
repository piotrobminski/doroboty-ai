# Current Product Behavior Register

This register describes the SQLite-backed teaching prototype with authenticated accounts and an optional local recruiter-AI gateway. Source coverage is not proof of executed checks or deployment; actual results belong in the relevant docs/tasks/ record, including docs/tasks/technologia-po-ludzku-app-redesign.md.

All application routes use the hash prefix. Accounts share one server scenario. Server sessions determine identity and enforce role/record access. All data remains synthetic. See docs/tasks/database-auth.md for this migration. The explicit build:s3 variant is separately labeled as a browser-only simulation; its roles are not security and its state is not shared across browsers.

Stable IDs are retained, including explicit removed entries. The legacy duplicate EMP-10 has been consolidated rather than assigned an ambiguous second identity.

## Current implementation limits

No real login, email, binary upload, production CVs, confidential roles, remote data backend, collaboration across devices, cloud analytics or live experiment measurement. The guided form simulates proposals locally; it does not demonstrate model quality. The optional gateway is not called by the form; any future provider reactivation requires separate transfer disclosure and verification of credits/limits. A static URL shares code, not local state; exported JSON contains the entire scenario. Human testing, publishing, CI results and course approval must be verified separately.
