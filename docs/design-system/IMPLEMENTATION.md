Read the [project guide](README.md), [source contract](technologia-po-ludzku/agent-kit/components.md), relevant [designer cards](technologia-po-ludzku/docs/design-system/v1/index.html#components), [host owners](HOST-COMPONENTS.md) and [acceptance checklist](VERIFICATION.md). This file describes receiving-project integration decisions. The whole-application implementation and its evidence are tracked in [STATUS.md](STATUS.md).

## Keep one host implementation

The source is vanilla HTML/CSS/ES modules; the product is React 19, TypeScript, Vite, React Router HashRouter and Base UI. Adapt the source's anatomy into existing JSX components. Do not use dangerouslySetInnerHTML to mount jobCardMarkup/offerMarkup, load source app.js/job.js/create-job.js, replace host data with jobs.mjs or add a second control library. The source renderers are readable executable anatomy references.

Reuse Base UI behavior, the existing `render` composition API, labels, disabled/current/pressed states, focus restoration and existing form/domain operations. A missing visual recipe is an explicit host adaptation decision, not permission to remove real product behavior.

## Compose by task, not by color substitution

- **Listing (source c 03, c 12–c 17):** expressive entrance → visible search → area choices and additional facets → result count/sort/criteria → calm card list. Desktop side filters; narrow layout above results. A homepage image does not satisfy the listing's entry. Keep search on the page. The host now uses inline Base UI facet selects inside native details/summary at all widths; the obsolete ResponsivePanel was removed.
- **Offer (c 02–c 07, c 17–c 20):** contextual return → graphite title band → readable facts/narrative → application action panel. Preserve long titles, honest missing salary and company identity. On mobile preserve coherent reading/action order. Use the source's profiles rather than tinting the old hero.
- **Editor/form (c 08–c 11, c 20–c 25):** task introduction, readable groups, validation text, next action and preview. The source has 3 stages; do not force an existing host editor into 3 stages as a side effect of styling without an explicitly scoped behavior change. Field/card/step typography and geometry remain useful references.
- **Records, profiles and settings:** compose documented surfaces, type, facts and actions around existing host semantics. These routes have no one-to-one source mockup; label the new composition as a host decision with anatomy, responsive behavior and states. Preserve role-specific omissions and snapshots.

The current runtime uses only the approved angular PNG and system font stacks. Both reference kits remain immutable historical/source inventories.

## Interaction and accessibility

Stable save name + aria-pressed, meaningful links versus actions, visible focus on paper and graphite, named modal focus containment/return, error text plus linked fields, and recovery after chip/result removal are required checks. Keep read-only facts/tags noninteractive. Preserve existing pointer/disabled behavior and reduced-motion paths; changing the palette is not a reason to remove interaction feedback.

Base UI already owns dialog/focus behavior in the host. Do not add the source keepDialogFocus helper over Base UI without a demonstrated gap; it is a standalone recipe, not a replacement for tested host primitives. Source choice controls are native; this host's Base UI Select must retain its own keyboard/name/value semantics and a 14px inset-equivalent chevron treatment, not a fake native role.

Use the [acceptance checklist](VERIFICATION.md). Full source checks verify the imported material, not a React migration or a complete WCAG audit.
