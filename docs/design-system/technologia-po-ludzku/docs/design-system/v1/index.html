F04 / dostępność

Wymagania i plan testów

R Dla wdrożenia web proponujemy cel WCAG 2.2 AA. To cel do potwierdzenia, nie deklaracja zgodności gotowego produktu. Oficjalne źródła sprawdzono 13.11.2026: normatywne WCAG 2.2, Quick Reference i wzorce APG. Dokumenty Understanding wyjaśniają kryteria; APG pomaga dobrać interakcję i nie jest normatywnym kryterium WCAG.

T Bieżąca analiza obejmuje inspekcję wizualną, wybrane przejścia UI i uzupełniający odczyt źródeł. Nie wykonano pełnego audytu czytnika, wszystkich kombinacji klawiatury, zoomu, forced-colors ani urządzeń dotykowych. Istnienie aria-* nie jest wynikiem takiego testu.

Kryteria i sposób sprawdzania

1.1.1 · A

Znaczące obrazy wymagają tekstowej alternatywy; dekoracje mogą być pominięte. W3C: non text content.

T Zbadać kontekst logo, kolażu i diagramów, nie nadawać wszystkim identycznego alt.

1.3.1 · A

Relacje i struktura muszą być dostępne programowo lub w tekście. W3C: info and relationships.

T Listy, nagłówki, definicje faktów, fieldset i label odzwierciedlają wizualną strukturę.

1.4.1 · A

Informacja nie może polegać wyłącznie na kolorze. W3C: use of color.

T Build/Apply/Lead mają znak i nazwę; błędy mają tekst.

1.4.3 · AA

Tekst: 4.5:1; duży tekst: 3:1. Duży oznacza co najmniej 18pt lub 14pt bold. Wyjątki obejmują m.in. logo, tekst incydentalny i nieaktywne kontrolki. W3C: contrast minimum.

T Liczyć parę tekst/tło dla faktycznej wielkości; nie stosować wyjątku logo do nazwy stanowiska.

1.4.4 · AA

Tekst można powiększyć do 200% bez utraty treści/funkcji; wyjątki obejmują napisy i obrazy tekstu. W3C: resize text.

T Tytuł, tagi, formularz i dialog w powiększeniu; zwykłe zrzuty mobile nie zastępują tego testu.

1.4.10 · AA

Dla treści przewijanej pionowo: reflow do szerokości 320 CSS px bez utraty informacji/funkcji i przewijania w dwóch kierunkach; wyjątek dla treści wymagającej układu 2D. W3C: reflow.

T Lista ofert i formularz nie są tabelą 2D; przetestować 320px i odpowiednik 400% na 1280px.

1.4.11 · AA

Niezbędne wizualne części kontrolek i stanów: 3:1 względem sąsiednich kolorów; wyjątki m.in. nieaktywne elementy i niezmodyfikowany wygląd kontrolowany przez user agenta. W3C: non text contrast.

T Nie każda dekoracyjna linia karty przenosi informację. Sprawdzić obrysy pól, focus i niezbędne ikony osobno.

1.4.12 · AA

Po nadpisaniu: line-height 1.5, odstęp po akapicie 2em, tracking.12em, word-spacing.16em — bez utraty treści/funkcji. To test odporności, nie wymóg takich wartości domyślnych; wyjątek dotyczy właściwości nieużywanych w danym języku/skrypcie. W3C: text spacing.

T Sprawdzić tagi, trzy etapy, formularz i sticky akcje jednocześnie po zmianie odstępów.

2.1.1 · A

Funkcje dostępne klawiaturą, poza wyjątkami wymagającymi ścieżki ruchu. W3C: keyboard.

T Wyszukaj, zmień filtry, zapisz, otwórz dialog, przejdź formularz bez myszy.

2.4.3 · A

Kolejność focusu zachowuje sens i możliwość obsługi. W3C: focus order.

T Sprawdzić przejścia etapów, błąd, zamknięcie dialogu i usunięcie kryterium.

2.4.7 · AA

W trybie obsługi klawiaturą focus ma być widoczny. W3C: focus visible.

T Zbadać każdą kontrolkę, także file, textarea i przyciski na graficie.

2.4.11 · AA

Element z focusem nie może być całkowicie zasłonięty przez treść utworzoną przez autora. W3C: focus not obscured minimum.

T Sticky podglądu, panel boczny i ramę dialogu sprawdzić przy małej wysokości. AA nie oznacza tu wymogu całkowitego braku jakiegokolwiek przykrycia.

2.5.8 · AA

Cel co najmniej 24×24 CSS px albo spełnienie reguły odstępów. Wyjątki: równoważny cel, inline, wygląd user agenta, niezbędny rozmiar. W3C: target size minimum.

T Mierzyć cały klikalny label/przycisk i otoczenie, nie glif. Systemowe 44px proponujemy jako wygodny cel projektowy, nie próg tego kryterium.

2.5.5 · AAA

Cel co najmniej 44×44 CSS px; kryterium ma wyjątki m.in. inline, równoważnego celu, user agenta i niezbędności. W3C: target size enhanced.

T Nie nazywać całego produktu AAA z powodu pojedynczych kontrolek 44px. Docelowy poziom v1 pozostaje rekomendacją AA.

3.3.1 · A

Automatycznie wykryty błąd opisuje się tekstem i identyfikuje błędny element. W3C: error identification.

T Pusta nazwa i poziom mają komunikaty; sam obrys nie wystarczy.

3.3.2 · A

Pola wymagające danych otrzymują etykiety lub instrukcje. W3C: labels or instructions.

T Wymagane/alternatywa link–CV i format kwot są zrozumiałe przed błędem.

3.3.3 · AA

Znana sugestia naprawy błędu jest podana, z wyjątkami dotyczącymi bezpieczeństwa lub celu treści. W3C: error suggestion.

T Dla górnej pensji mniejszej od dolnej komunikat mówi, co zmienić.

4.1.2 · A

Nazwa/rola i modyfikowane stany oraz wartości są dostępne programowo. W3C: name role value.

T Sprawdzić select, radio, pressed zakładki, aria-current kroku i nazwę dialogu w czytniku.

4.1.3 · AA

Komunikaty statusu są dostępne technologiom asystującym bez otrzymania focusu. W3C: status messages.

T Zbadać licznik, toast i status szkicu. Obecność role=status w HTML nie dowodzi poprawnego odczytu.
