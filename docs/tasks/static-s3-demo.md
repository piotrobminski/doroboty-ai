# Drag-and-drop static demo for object storage

## Intent and accepted scope

The user requested one folder for S3-style storage and explicitly selected a static demo with simulated login and browser-only data after being informed that object storage cannot run the existing Node/SQLite API. This is an explicit static-demo build mode, not an automatic fallback on API failure. Preserve normal server authentication/database behavior and existing uncommitted production-bundle work, including unrelated user-owned files.

## Acceptance criteria

- `npm run build:s3` creates one upload folder with index.html and all local runtime assets; no Node process, npm installation, API or cloud credentials are required on the host.
- The static build uses existing synthetic accounts with Test1234 as a demonstration-only check, shared Zod/domain validation and browser-local persistence in a separate storage key. No real account security or synchronization across browsers is claimed.
- Keep offer publication, drafts, candidate submission, immutable application/CV snapshots, employer decisions, operator import/export/reset and role-specific views coherent within that browser. Corrupt/unavailable storage must preserve recoverable data and failed writes must not claim success.
- Clearly label the simulation on every route and explain account/storage limitations on login, settings and privacy screens, using existing Technologia po ludzku Notice/PageTitle/FormSection components (HP02/03/06). No new tokens or immutable-kit edits.
- Check the built folder through a file-only HTTP server with no API: desktop/mobile/320px, keyboard/errors/recovery, browser isolation and a candidate-to-employer journey. Compare the affected notice/form anatomy to source profiles. Run ./scripts/verify for the normal server build and focused static-build tests; inspect output for secrets/runtime data/history.
- Document uploading folder contents, index.html hosting and per-browser data boundaries. Update FEATURES.md and report actual local results separately from any cloud deployment.

## Design and implementation

Use the existing Notice feedback and established page/control compositions without a parallel design. The opt-in static adapter shares the domain model and version-1 scenario JSON shape; it never calls the API. Keep its localStorage key separate from legacy saves and server mode. Preserve the original corrupt value for explicit download/reset recovery. S3 static hosting supports client-side scripts, not the server API; see [AWS static website hosting](https://docs.aws.amazon.com/AmazonS3/latest/userguide/WebsiteHosting.html).
